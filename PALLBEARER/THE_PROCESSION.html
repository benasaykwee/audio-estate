What changed, and the one sentence that matters

On 22 August this report said PALLBEARER had never been built into a loadable plugin, and that the next run would be the first that could reach the macOS job. It did. The first green run produced a binary within hours, and three more followed. Four pallbearer-plugins-macos artifacts sit on GitHub, 1.96 MB each, dated 23 August, none expired.

Nobody has downloaded them. The instrument has had a body for four days and has not been outside once. That is now the entire critical path: not a build problem, not a code problem, a collection problem.

The diagnosis held exactly. The LAW 1 guard was the only thing standing between this project and a binary. Run #2 failed. Run #3, carrying the architecture-blind fix, went green and built. Nothing else needed changing.

The mutation ladder — proof the suite is worth what it claims

Ten deliberate sabotages of the core. A gate that has never been shown to fail is a gate nobody has tested.

The subtlest of the three is worth keeping in mind. Removing the fingering brain's free pass for open strings makes it fret notes a bassist would always play open. Every individual sample still looks fine. Only the choice of string changes, which is the hardest class of bug to hear and the one no byte-comparison will ever catch.

The CORONER seam — clean contract, missing transport

CORONER computes a correct PALLBEARER patch and has nowhere to send it.

The good news is how little is wrong. Whoever wrote routeToPallbearer read PALLBEARER's real parameter table rather than guessing, down to clamping tone to [200, 12000] and decay to [0.5, 12], which are PALLBEARER's own bounds to the digit. It also declines to guess pluck position, with a comment saying a wrong answer there is worse than the default because it moves the whole character of the sound. That instinct should survive.

And one thing to fix before it can bite. routeToPallbearer does not emit couple, so the seam is safe by omission rather than by design. Stiffness is precisely the feature that would tempt a future routing rule to set coupling, and PALLBEARER's String Coupling still self-oscillates. Fix the divisor before that line gets written, not after.

Still open, and unchanged since 20 August

String Coupling self-oscillates. Re-measured today: a six-string at couple: 0.30 grows +21.3 dB over five seconds instead of decaying. Four-string breaks near 0.42, five-string near 0.34, six-string near 0.27. Multiply each by (N−1) and the three collapse to 1.26, 1.36, 1.35, which is the diagnosis: the bus is the raw sum of every other string's bridge output, so loop gain scales with string count.

One divisor fixes it. Nothing caught it because a drone pinned at the soft clipper's ceiling has no NaN, never throws and never exceeds 1.6 — the best-behaved signal in the fuzz corpus. Full working in THE_VIEWING.html.

The next five things — yours

  1. Download the binary that has been waiting since Sunday10 min
    Run #6 on 23 August, artifact pallbearer-plugins-macos, 1.96 MB, not expired. Safari may auto-unzip it to the Desktop rather than Downloads. This is the whole critical path and it is four days cold.
  2. Install it and run auval -v aumu Pbrr Basy20 min
    The xattr -dr com.apple.quarantine step is the one that matters; right-click-Open is for apps and will not substitute. You want AU VALIDATION SUCCEEDED on the last line. This is the estate's first aumu, so the validator will exercise MIDI, which nothing here has been through.
  3. Play it from the P-155 and tell me what is wrong with itan hour
    Still the highest-value thing you can do and still not done. Every number in this report is a measurement; not one is a judgement about whether it sounds like a bass. Whether the fingering brain picks the string a player would is a question only ears answer.
  4. Say what String Coupling is forfive minutes
    Carried over from the first edition and now blocking more than it was. I know how to make it stable; I do not know whether the top of the dial should be rich sympathetic ring or the drone it currently is, kept deliberately and relabelled.
  5. Decide the Developer ID questionmoney, not code
    The notarisation step is already written into the workflow and gated on secrets existing, so this is now genuinely a two-secret change rather than a project. It gates anyone else ever installing these.

The next ten things — mine

Reordered since the first edition. The CORONER seam did not exist then.

  1. Build the #p= reader in pallbearer.html
    New at number one. Decode base64url, parse {v, p}, refuse an unknown major version, hand p to the existing sanitize(), and round-trip it in the harness through the same decode CORONER performs. It is the only thing between a computed patch and a played one.
  2. Normalise the coupling injection and kill the oscillator
    Divide by the number of contributing strings. JS first, mirror to PallbearerCore.h, re-emit parity, re-bless the eleven baselines deliberately and say so in the commit. Now also a seam prerequisite.
  3. Build the stability gate that would have caught it
    Pluck once, sweep couple across its range against every tuning, assert the last window is quieter than the window at one second. The same assertion is still missing from RIGOR and NECROPHONE.
  4. Harden the MIDI surface
    All-notes-off, sustain pedal, pitch bend, overlapping note-ons on one string, note-off for a note never started, note-on at the last sample of a block. If auval finds something, it will be here.
  5. Add sanitizeReport() beside sanitize()
    Purely additive, so no existing number moves. Turns a silent importer into one that can say "I clamped decay from 14 to 12," which makes CORONER's own admission that its thresholds are calibrated guesses visible rather than buried.
  6. Pin couple: 0 in the tuning test and gate the value, not the limit
    Restores the honest 0.088 cents and makes the next 115% drift loud instead of silent.
  7. Put provenance on renders
    {L, R, sr, meta:{coreVersion, patchHash, seed, note, velocity}}. Additive, and it closes a measurement loop with CORONER that is otherwise anecdotal.
  8. Stereo out
    Both channels are still identical. Two pickups at different positions along the string is a physically motivated answer that costs nothing per sample.
  9. Oversample the drive stage
    It aliases at high settings, and the Interchange warns that oversampler taps are the first thing the compiler wants to fuse. Arrives with a parity re-run at all three optimisation levels rather than a claim.
  10. Extract a real patch library
    Nine presets still live as a literal inside the HTML, so the plugin cannot see them. One file, both faces, and a gate that every preset loads and renders without clipping.
