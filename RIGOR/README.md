# RIGOR

*"The body stops moving."*

A dynamics processor in the FabFilter Pro-C lineage. Second of three — AUTOPSY opened the body, RIGOR holds it still, the limiter closes the lid.

One DSP core, two bodies: a browser instrument and a JUCE plugin, proven identical to the last bit.

**Status:** v0.6 — 2026-08-15

---

## Run it

```bash
open rigor.html                 # the browser instrument, no build step
node tests/rigor_test.js        # core harness
node tests/rigor_ui_test.js     # UI-logic harness (headless)
node tests/rigor_regression.js  # byte-stable rendered-buffer baselines
node rigor_sync.js              # re-embed the core into the HTML
```

Parity gate:

```bash
node tests/parity_emit.js
g++ -std=c++17 -O2 -ffp-contract=off -o core_parity tests/core_parity.cpp && ./core_parity
```

## The two laws, and a third

1. **necromath is mandatory** for every transcendental. `NM` in JS, `nm::` in C++ — portable sin/cos/exp/log/pow10 built from fixed-order IEEE operations. v8 and libm disagree in the last 1–2 ulp, and an IIR turns that into audible drift. `sqrt` stays native (IEEE-exact).

2. **`-ffp-contract=off`.** GCC will FMA-fuse `a*b+c` into a single rounding where JavaScript performs two.

3. **New to RIGOR: the Settling topology is the canary.** It runs a feedback detector, so each sample's gain feeds the next sample's detector through a *nonlinear* gain computer. A one-ulp disagreement doesn't just persist there, it compounds. If parity ever breaks, check Settling first.

## Design notes worth knowing

**The gain computer's `>=` is load-bearing.** With `>`, a hard knee (`W = 0`) leaves exactly one point uncovered — `x` precisely at threshold, where `0 < 0` and `0 > 0` are both false — so it falls into the quadratic branch and evaluates `0/0`. NaN into the envelope, and a feedback topology never recovers.

**The linear branch is `d*(invR-1)`, not `(T + d*invR) - x`.** Algebraically identical, but the textbook form computes `y` then subtracts `x`, and `T + (x-T)` does not always return exactly `x` in floating point. That residue makes a 1:1 ratio produce ~1e-15 of gain reduction instead of zero, which breaks the bitwise null test.

**The envelope smooths the gain, not the level** — so attack time means one thing regardless of ratio and overshoot. Settling deliberately does the opposite, because level-dependent attack is what makes an optical cell behave like one.

**Attack is defined as time-to-63.2%-of-target-GR.** Stating the definition is what makes the harness assertion mean something; our numbers will not match Pro-C's numerically, and that is fine.

**The dry tap sits after the delay line.** Tap it before and parallel mix comb-filters instead of mixing.

**Auto makeup is analytic** — the gain computer evaluated at 0 dBFS, negated. A measured estimator would make output depend on playback history and break byte-stable regression.

## The four styles

**Four topologies, four styles** — measured, not assumed, and only true since
round 8. For five rounds Fresh and Spasm shared a signal path and rendered
bit-identically; Spasm was a good preset wearing a topology's name. It now has
its own peak-follower decay, 2 ms against the house 15 ms, which lets the
follower fall away between transients so each hit is seen at close to full
height. That IS the punch character. See `docs/STYLES_MEASURED.md`, which is
now generated by `tests/rigor_styles.js` rather than maintained by hand — the
hand-maintained version is how it came to assert the opposite of the code.

| | **Fresh** | **Settling** | **Spasm** | **Repose** |
|---|---|---|---|---|
| | Clean | Opto | Punch | Bus |
| Topology | feedforward | **feedback** | feedforward | feedforward |
| Detection | peak | RMS 10 ms | peak | RMS 50 ms |
| Envelope on | gain | **level** | gain | gain |
| Peak-follower decay | 15 ms | 15 ms | **2 ms** | 15 ms |
| Level-dependent attack | — | **yes** | — | — |
| Default ratio / knee | 4:1 / 6 dB | 3:1 / 9 dB | 6:1 / 0 dB | 2:1 / 18 dB |
| Default attack / release | 10 / 200 ms | 25 / 300 ms | 0.5 / 80 ms | 30 / 400 ms |

The first five rows are the *path*; the last two are only defaults written
into a case file when you pick the style. All four now differ on at least one
path row, and `tests/rigor_styles.js` checks every pair BOTH ways — same path
and same render — flagging any disagreement between the two.

A warning the step response earns: driven with a DC step, Fresh and Spasm
still read identically (−15.00 dB, 20.0 ms to 63.2%), because a step never
lets the follower decay. The difference only appears on material with gaps.
A step response is not a sufficient probe of a compressor's identity, and
believing it was is how the previous claim survived five rounds.

## v0.6 additions

**Spasm has a topology.** See above. Eight regression baselines moved, all of
them Spasm cases and no others, which is the signature the change should have.

**Selectable detector oversampling — 2×, 4× or 8×.** `detOsX`, a set rather
than a range: 3 is not a cheaper 4. The phase offsets nest (frac = p/os), so
more phases can never report a *lower* peak — an invariant the harness
asserts rather than a behaviour it hopes for. It matters **only on isolated
transients**: on a sustained tone the sample index already sweeps the
fractional offsets densely, and 8 phases agree with 4 exactly. On a
band-limited blip whose peak sits between samples, 8× recovers up to 0.19 dB
that 4× misses, and 4× up to 0.59 dB that 2× misses. `detOsX: 4` reproduces
every pre-round-8 baseline bit-for-bit.

**Hold tapers into release.** `holdTaper` 0..100. Hold was a cliff — frozen
for N samples, then full-speed release — and on material that retriggers near
the boundary that switch is audible. The release coefficient now eases in
across the hold. At 0 the branch is **skipped entirely** rather than evaluated
with a unity coefficient, which is what makes "no change" mean bit-identical
rather than nearly so.

**A CPU budget for the twin.** `tests/core_bench.cpp`. The published figure
was the JS number with "the C++ twin is materially faster" appended, which was
a hope. It is 47× realtime worst case against the JS core's 13×, compiled with
the same `-ffp-contract=off` the parity gate requires — a faster build that
fails parity would be a figure for a different plugin.

**Reduced motion no longer switches the instrument off.** It was
`if (!reduce) frame();`, which froze the meters and the chart entirely for
exactly the users least able to afford a frozen meter. It now throttles to
~10 fps. The decision lives in `UIH.redrawInterval` so the harness can check
it without a browser.

**Crossover drag-swap, A/B case diffing, gain-reduction CSV export**, and
text alternatives on all three canvases.

## v0.2 additions

**Delta listening** — hear only what was removed. `y − y·g`, which is *exactly* zero when the compressor is idle, because `g` is then exactly 1. Silence is the correct sound of a compressor doing nothing, and here it is audibly silent rather than nearly so.

**Mid/side placement** — an exact matrix, the same algebra AUTOPSY proved. Everything downstream is untouched, which is why placement is a matrix and not a mode.

**True-peak metering**, 4× polyphase. `TP_TAPS = 8` is empirical and load-bearing: raising it without redesigning the window makes the meter *worse* (8 taps: −0.049 dB error; 12 taps: +0.451 dB), because a Blackman window over a short span narrows the passband and the unity-DC normalisation then overshoots near fs/4. The harness pins the tap count so nobody "improves" it by accident.

**LUFS** — momentary, short-term and integrated with the two-stage BS.1770 gate. K-weighting is designed parametrically rather than copied from the standard's 48 kHz table, so it is correct at 44.1, 88.2, 96 and 192 k too. EBU Tech 3341 case 1 reads −22.99 against a −23.0 target.

**Release curve** — blends the exponential recovery toward a constant dB-per-sample ramp. `curve = 0` is bit-identical to the plain one-pole, so it costs nothing unused.

**Denormal guard, auto-threshold, sidechain analyser tap.**
