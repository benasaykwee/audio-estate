# RIGOR — full audit, 16 August 2026

Scope: `RIGOR/` only. Nothing outside it was written. One finding lives in
`shared/` and is reported rather than fixed, because RIGOR is not permitted to
change shared code.

Everything below was found against a suite that was **entirely green** when the
audit started.

---

## 1. A single non-finite sample locked the audio thread

**Severity: highest. This is the finding that justified the audit.**

A `±Infinity` sample anywhere in the input caused RIGOR to stop and never
return. Not a click, not a dropout — the audio thread hangs, which in a DAW
means a frozen host and a force quit. It reproduced at every style, at every
block size, in single band and multiband. Only `bypass` survived, because it
never touches the detector.

The chain:

```
input sample = ±Inf
  -> peak follower holds Inf
    -> ND.linToDb(Inf)
      -> NM.log10(Inf)          <- iterates, never converges
```

`ND.linToDb` has always guarded the **low** end — 0, negative and denormal all
clamp to −600 dB — which is exactly why digital silence has never been a
problem and why nobody noticed. Nothing guarded the high end.

Hosts produce non-finite samples for real: a divide-by-zero in an upstream
plugin, an uninitialised buffer, a badly behaved instrument. This is not an
exotic input.

**Why nothing caught it.** The fuzzer hammers the *state* — random parameters,
hostile combinations, nonsense in every field. It had never once handed the
engine a bad *sample*. Every NaN assertion in the project was about the output,
not the input.

**Fixed in RIGOR** with an input guard in the engine, on the external sidechain,
and — separately — in the multiband wrapper *before* the splitter, because an
Inf entering a crossover biquad becomes part of that filter's state permanently
and the band engines' own guards would be on the wrong side of the wound.

Non-finite becomes silence. Not a clamp to some large finite value: there is no
honest magnitude to assign to NaN, and a huge one would slam the detector and
duck the whole track for the length of the release. Zero is the only reading
that invents nothing.

No regression baseline moved. Every legal sample is finite, so the guard is
invisible to all 35 baselines and to `mix = 0` bit-exactness.

**Still open, in `shared/`, NOT fixed:** `NM.log`, `NM.log10` and `NM.exp` loop
forever on non-finite arguments, and `NM.log`/`log10` also loop on `0` and on
negatives (ND happens to guard those two before they reach NM). `ND.linToDb`
and `ND.dbToLin` therefore hang on `±Inf`. **AUTOPSY, CASKET and NECROPHONE all
use the same substrate and are presumably exposed the same way.** RIGOR is now
immune regardless, because it guards its own input — which is where the guard
belongs anyway. Fixing the substrate needs Ben's permission and should probably
be checked against the other three programs at the same time.

## 2. Round 9 shipped three parameters no host could reach

`deltaBand`, `scBand` and `tsSplit` were added to the core, to the C++ twin and
to the browser instrument — and never to the plugin. A host could not automate
them or see them.

**Why the plugin lint missed it:** it asserted

```js
ok(declared.length >= 25, 'layout declares ' + declared.length + ' parameters');
```

Thirty-five were declared, so a floor of 25 passed comfortably while three were
missing. **A floor cannot notice something absent; it can only notice a
catastrophe.** Same species as the version assertion that named its own expected
value and "passed" for two rounds while the core and the twin disagreed.

**Fixed:** the three parameters are now declared and applied, and the assertion
is derived — every field in `defaultState()` must map to a declared parameter or
appear in an explicit `NOT_A_PARAM` list with a reason. Proven to bite by
removing each of three parameters in turn.

## 3. Two things had no parity coverage at all, and one was the guard

The coverage census found `bypass` and `scListen` had never appeared in a parity
case. Hostile input had none either, which meant the new guard would have been
unverified arithmetic in the twin.

**Fixed:** six new parity cases covering poisoned input (single band, feedback
topology, and multiband so the splitter guard is exercised), bypass, and
sidechain listen at one and two bands. Parity went **36,998 → 50,718**, all
bit-exact.

## 4. Dead and duplicated files

- **`tests/_fz_probe.js`** — a 20 KB orphan, referenced by nothing. It was a
  pre-round-8 copy of the fuzzer still carrying the *fitted output bound that
  round 8 disproved*, and it **failed** when run. My own scratch litter.
  Deleted.
- **`tools/embed.js`** — round 9 added a second embed tool without noticing
  `rigor_sync.js` had done the job since the beginning. That is precisely the
  "a rule with two copies" defect round 9 had just flagged elsewhere, committed
  by the person flagging it. CI and the README have always named
  `rigor_sync.js`. The two things the newer tool had that the older one did not
  — a `--check` mode and an explicit law 4 order assertion — are folded into
  `rigor_sync.js`, and the duplicate is deleted.

## 5. Three new harnesses, and CI now runs them

- **`tests/rigor_stress.js`** (50 assertions) — hostile input samples across ten
  configurations, recovery behaviour, determinism, and block boundaries landing
  inside the control interval.
- **`tests/rigor_coverage.js`** — a census, not a test of correctness. For every
  state field: sanitised? read by an engine? ported to the twin? reachable from
  a host? reachable from the browser? named by any harness? `--strict` fails on
  an unexplained gap, so a field added later must be decided about rather than
  defaulted into.
- **`tests/rigor_mutate.js`** — carried over from round 9, now in CI.

CI also now runs `rigor_sync.js --check`, which writes nothing and fails if the
browser instrument is running different code from the one the tests just passed
on. That had already happened once.

## 6. Twelve parameters are automatable but have no knob

`hold_taper`, `detect`, `det_os_x`, `delta_band`, `sc_band`, `ts_split`, and all
six band mute/solo controls exist as host parameters with no control in the
bespoke plugin editor. The browser instrument has all of them.

This is a feature gap rather than a defect — they work, and automation reaches
them. It is now **on the record** as a list in the plugin lint, so anything new
that lands without a control fails until somebody chooses, and the lint also
fails if an entry becomes stale.

## 7. My own tools and assertions were wrong five times

Consistent with this project's history, and worth writing down rather than
quietly fixing:

1. The coverage tool's "unused exports" check used `[\.\b]`. Inside a character
   class `\b` means **backspace**, not a word boundary, so it only ever matched
   `.name` and reported five heavily-used exports as dead.
2. The coverage tool called four fields unread because they are read through
   `releaseMs()` and `autoMakeupDb()`. Now recorded as helper indirections.
3. My first law-3 check matched each embed block *including* its terminating
   tag, then searched the result for terminating tags. It "failed" a law that
   holds.
4. The stress test first demanded that a poisoned engine be **identical** to one
   that never saw the poison. The guard turns poison into silence, so the
   damaged engine genuinely received a different signal. Recovery means the
   difference **decays**, not that it never existed. The second attempt then
   asserted an absolute floor of `1e-9` and failed three styles behaving exactly
   as designed — a fitted number, again. The assertion now derives its bound
   from the slowest legal path: auto-release runs a second follower at eight
   times the release, so over five release constants the least legal decay is
   `e^(-5/8) = 0.535`. Settling lands at 0.436 — a bound with teeth.
5. The `scBand` test asserted the wrong direction twice. Without a band
   sidechain the low band is compressing hard against its **own** steady tone,
   so switching its detector to the mostly-quiet high band makes it *louder*
   overall. The comparison had to move from between-conditions to
   within-condition-across-time.

Running tally for the project: **roughly sixteen bad assertions of mine against
eight real bugs.** The lesson holds — suspect the assertion first — and the two
newest cases add a corollary: *an assertion that measures across a time window
must account for the time constants of the thing it is measuring.*
